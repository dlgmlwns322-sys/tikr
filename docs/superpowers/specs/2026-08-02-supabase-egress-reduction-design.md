# 티커 Supabase 사용량 추가 절감 설계

마지막 수정일: 2026-08-02 02:05 (KST)

## 목표

현재 UI에서 사용하지 않는 24시간 코인 수집과 과도한 REST 응답을 줄여 Supabase 무료 egress 재초과 위험을 낮춘다. 기존 데이터는 삭제하지 않고 서비스 기능을 유지한다.

## 확정 범위

1. `upbit-quote` 실시간 수집 대상을 `BTC_KRW` 하나로 줄인다.
2. `macro-poll`에서 `binance-quote` 호출을 제거한다.
3. 5분마다 실행되는 `macro-poll` 안에서 업비트 호출은 15분 간격으로만 실행한다. 한국장 KIS 수집 주기는 기존 5분을 유지한다.
4. 홈 당일 조회의 `select('*')`를 실제 사용하는 `price,percent_change,fetched_at`으로 제한한다.
5. 차트의 `quote_history` 폴백 조회 상한을 2,000행에서 500행으로 줄인다. 정상 경로인 Yahoo intraday 또는 `daily_ohlc`는 유지한다.
6. ETH·XRP·USDT 기존 행과 `binance-quote` 함수 자체는 삭제하지 않는다. 자동 호출만 중단해 복구 가능성을 보존한다.
7. 기존 미국·한국 장외 게이팅과 3일 이후 일 1행 프루닝은 유지한다.

## 데이터 흐름

- 한국장 개장 중: `macro-poll` → KIS 지수·종목은 5분마다 갱신한다.
- 환율: 기존처럼 5분마다 확인하되 가격이 같으면 저장하지 않는다.
- 비트코인: 15분 경계에서만 `upbit-quote`를 호출하고 `BTC_KRW` 1행만 저장한다.
- 바이낸스·ETH·XRP: 자동 수집하지 않는다.
- 화면: 홈은 필요한 세 필드만 받고, 차트 폴백은 최대 500행만 받는다.

## 검증

- 정적 검사로 `macro-poll`에서 바이낸스 호출이 없고 업비트 15분 게이트가 있는지 확인한다.
- `upbit-quote` 응답·DB 삽입 대상이 `BTC_KRW` 하나인지 테스트한다.
- 프론트 쿼리에 `select('*')`와 `limit(2000)`이 남지 않았는지 검사한다.
- 전체 테스트 후 `macro-poll`, `upbit-quote`를 배포하고 실호출 응답을 확인한다.
- 월요일 한국장과 미국장 개장 후 각 심볼의 `fetched_at` 갱신 재개를 확인한다.
- Supabase 대시보드 egress는 며칠간 수동 확인한다. 사용량이 계속 빠르면 서버 집계 RPC를 2단계로 검토한다.

## 제외

- 기존 데이터 삭제
- 신규 테이블·RPC·외부 서비스 추가
- UI 기능 변경
- Binance Edge Function 삭제
